# 1. 要求仕様書 (User Requirements Specification)

## 1.1 背景と目的
### 背景
製造現場において、製品の品質データ（パトロール結果、不具合報告）と、製品から収集されるセンサーデータ（ログデータ）が個別に管理されており、不具合発生時の要因解析に多大な工数を要している。現状は熟練エンジニアの経験と勘に依存しており、解析精度やスピードに個人差が生じている。

### 目的
*   **工数削減:** 散在するデータを一元的に可視化し、情報収集時間を短縮する。
*   **脱・属人性:** 統計・機械学習を用いた自動解析により、誰でも客観的な要因分析を行えるようにする。
*   **予兆検知の高度化:** パトロール結果とセンサーデータの相関を分析し、不具合の予兆を早期に発見する。

## 1.2 対象ユーザー
*   **品質保証（QA）:** 市場不具合の原因究明、再発防止策の策定。
*   **設計・開発:** 新機種の不具合傾向分析、設計パラメータの最適化。
*   **製造技術:** 設備条件と不具合の相関分析。

## 1.3 業務フロー（To-Be）
1.  **予兆検知:** 「不具合傾向表示」画面および「パトロール結果一覧」を用いて、現在発生している不具合のトレンドや異常を検知する。
2.  **詳細調査:** 「機番履歴表示」により、特定の不具合機体の時系列データを深掘りする。
3.  **要因特定:** 「不具合要因解析」機能を用い、不具合機と正常機のデータを比較。統計的に有意な差異（要因）を自動抽出する。
4.  **対策立案:** 解析結果（ランキング、グラフ）に基づき、対策すべきパラメータや部品を特定する。

## 1.4 制約事項
*   **データ:** 不具合データは立ち上げ期（数件）から量産期（数千件）まで扱うため、データ量に応じた解析手法が必要。
*   **環境:** イントラネット内での動作を前提とする。解析データは機密情報を含むため、セキュリティに配慮が必要。
