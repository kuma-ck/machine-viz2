# 2. 要件定義書 (System Requirements Definition)

## 2.1 機能要件

### 2.1.1 ダッシュボード（トップ画面）
*   システム全体の稼働状況、最新のデータ更新日、直近のアラート件数をサマリー表示すること。
*   各機能へのナビゲーションを提供すること。

### 2.1.2 不具合傾向分析 (Defect Trend)
*   機種シリーズ、期間、不具合分類等の条件でデータを検索・集計できること。
*   **時系列チャート:** 日次・週次での不具合発生件数推移を棒グラフで表示すること。
*   **分布チャート:** 製造月ごとの不具合発生分布を表示し、特定のロットへの偏りを可視化すること。

### 2.1.3 パトロール結果管理 (Patrol List)
*   自動監視ロジックによるパトロール結果（警告ランク、機番、検知内容）を一覧表示できること。
*   ランク（A/B/C）や機種でフィルタリングできること。

### 2.1.4 機番履歴・詳細表示 (Machine History)
*   特定の機番について、ライフサイクルイベント（製造、FW更新、修理、不具合）を時系列で表示すること。
*   特性値（センサーデータ）の時系列推移をグラフ表示できること。

### 2.1.5 不具合要因解析 (Factor Analysis)
*   **ファイル入力:** 解析対象データ（CSV/Excel/Parquet）をアップロードできること。
*   **自動解析:** データのサンプル数に応じて、適切な統計手法（Mann-Whitney U検定、ロジスティック回帰、LightGBM+SHAP等）を自動選択して実行すること。
*   **結果表示:** 不具合と相関の強い変数をランキング形式で表示すること。
*   **可視化:** 上位変数について、正常群と不具合群の分布比較グラフ（箱ひげ図等）を表示すること。

### 2.1.6 認証・権限
*   ユーザー名・パスワードによるログイン認証を行うこと。
*   ログインしていないユーザーのアクセスを制限すること。

## 2.2 非機能要件
*   **性能:** 10万行×1000列程度のデータに対し、3分以内に解析結果を返すこと。
*   **ユーザビリティ:** 専門的な統計知識がないユーザーでも、結果（NG方向、関連度）が直感的に理解できるUIであること。
*   **セキュリティ:** アップロードされた解析用データは、解析完了後にサーバー上から破棄すること（永続化しない）。
*   **可用性:** Webブラウザ（Chrome/Edge等）で動作すること。

## 2.3 技術要件
*   **Backend:** Python (FastAPI)
*   **Frontend:** HTML/CSS (Jinja2 Template), JavaScript (Vanilla)
*   **Visualization:** ECharts
*   **Database:** SQLAlchemy (SQLite/PostgreSQL)
*   **Data Analysis:** pandas, scipy, statsmodels, lightgbm, shap
